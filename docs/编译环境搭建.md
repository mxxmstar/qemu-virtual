## 目录结构
建议第一个模块使用“内核树外模块”方式开发。不要一开始把 hello.c 放进 Linux 内核的 drivers/，这样更容易理解模块编译和加载流程。

```text
    /home/ub22/mxxmstar/
    ├── linux/
    │   └── linux-6.12/linux-6.12.112/
    ├── modules/
    │   └── hello/
    │       ├── hello.c
    │       └── Makefile
    └── buildroot/
        └── buildroot-2025.02.15/
```
### 1. 创建 hello.c
在虚拟机执行：
mkdir -p /home/ub22/mxxmstar/modules/hello
cd /home/ub22/mxxmstar/modules/hello
vi hello.c
写入：
```C
#include <linux/init.h>
#include <linux/module.h>

static int __init hello_init(void)
{
    pr_info("hello: module loaded\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("hello: module unloaded\n");
}

module_init(hello_init);
module_exit(hello_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("mx");
MODULE_DESCRIPTION("First Linux kernel module");
```
module_init() 在执行 insmod 时调用，module_exit() 在执行 rmmod 时调用。
### 2. 创建模块 Makefile

```makefile
obj-m += hello.o

KDIR ?= /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15/output/build/linux-custom

all:
	$(MAKE) -C $(KDIR) M=$(CURDIR) ARCH=arm64 \
		CROSS_COMPILE=/home/ub22/mxxmstar/buildroot/buildroot-2025.02.15/output/host/bin/aarch64-buildroot-linux-gnu- \
		modules

clean:
	$(MAKE) -C $(KDIR) M=$(CURDIR) clean
```
注意，all: 和 clean: 下面的命令行必须使用 Tab 开头。
先确认 Buildroot 的内核构建目录：
```bash
cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15
ls -d output/build/linux-*
```
如果显示的不是 output/build/linux-custom，就用实际显示的目录覆盖 KDIR：make KDIR=/实际的/output/build/linux-目录
### 3. 编译模块
先确保内核已经成功编译：
```bash
cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15
make linux
```
然后编译模块：
```bash
cd /home/ub22/mxxmstar/modules/hello
make
```
成功后应生成：hello.ko
检查模块信息：
file hello.ko
modinfo hello.ko
它应该是 ARM64 Linux kernel module，不能在 x86_64 虚拟机宿主机上直接执行。
### 4. 放进 QEMU 根文件系统
建立 Buildroot rootfs overlay：
```bash
mkdir -p /home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay/root
cp hello.ko /home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay/root/
```
然后配置 Buildroot：
```bash
cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15
make menuconfig
```
进入：
```text
System configuration
  -> Custom skeleton
  -> Root filesystem overlay directories
```
填写：/home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay
也可以直接修改 .config，但推荐使用 menuconfig。

**在 Buildroot 2025.02.15 中，正确菜单路径是：**
```text
System configuration
  -> Root filesystem overlay directories
```
配置项名称是：BR2_ROOTFS_OVERLAY
可以直接编辑 Buildroot 配置，避免菜单操作：
```bash
cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15

sed -i 's|^BR2_ROOTFS_OVERLAY=.*|BR2_ROOTFS_OVERLAY="/home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay"|' .config

grep '^BR2_ROOTFS_OVERLAY=' .config
```
如果 .config 中还没有这一行，则执行：
```
echo 'BR2_ROOTFS_OVERLAY="/home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay"' >> .config
```

**准备模块文件：**
```bash
mkdir -p /home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay/root

cp /home/ub22/mxxmstar/modules/hello/hello.ko /home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay/root/
```
**然后重新生成根文件系统：**
```bash
make
```

### 5. 启动 QEMU 并加载模块
```bash
cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15
./output/images/start-qemu.sh serial-only
```
进入 QEMU 后：
```bash
uname -r
uname -m
ls -l /root/hello.ko
insmod /root/hello.ko
lsmod | grep hello
dmesg | tail -20
rmmod hello
dmesg | tail -20
```
应该看到：
```bash
hello: module loaded
hello: module unloaded
```
### 6. 修改代码后的流程
修改 hello.c 后：
```bash
cd /home/ub22/mxxmstar/modules/hello
make clean
make
cp hello.ko /home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay/root/

cd /home/ub22/mxxmstar/buildroot/buildroot-2025.02.15
make
```
然后重启 QEMU。
```bash
poweroff
```
模块必须使用与 QEMU 正在运行的内核匹配的源码、配置和版本编译。检查：
```bash
uname -r
modinfo /root/hello.ko
```
如果出现 invalid module format，优先检查内核版本、内核配置、架构和交叉编译器是否一致。
另外，也可以直接确认配置是否生效：
```bash
grep '^BR2_ROOTFS_OVERLAY=' .config
```
应显示：
```text
BR2_ROOTFS_OVERLAY="/home/ub22/mxxmstar/board/qemu-aarch64/rootfs-overlay"
```
